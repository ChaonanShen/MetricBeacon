# Proposal：自然语言驱动、可沉淀的可观测性指标分析工作台

> status: current product baseline
> acceptedAt: 2026-07-15
> supersedes: [`product_design.md`](product_design.md) for current product scope and acceptance direction
> architectureNote: 本文中的运行形态用于表达产品职责；已实现的服务边界、数据所有权和接口约束仍以 ADR、`../implementation/code_skeleton_design.md` 与实际代码为准。

本文定义 Torchbearing 的产品定位、用户价值、功能边界、核心概念和代表性产品行为，作为后续具体功能 Proposal、产品原型与系统架构设计的共同依据。

Torchbearing 的产品定位是：

> 嵌入 Grafana 的自然语言 Prometheus 指标分析工作台。用户或可信告警从观测问题出发，由 Agent 使用真实数据完成查询和可视化，将有价值的分析过程沉淀为可恢复、可分享和可复用的团队经验，并使关键行为保持可追溯。

本提案描述最终产品应具备的完整能力和边界。每个功能增量仍需形成独立、平级、可评审和可验收的功能 Proposal。

## 1. 动机 / 用户故事

### 1.1 知道问题，但不知道指标

> 当我收到“checkout 服务变慢”的反馈时，我知道需要观察延迟、请求量和错误率，但不知道团队使用了哪些指标、标签和 PromQL。我希望直接描述问题，先得到一张基于真实数据的可信图表，再决定下一步查什么。

用户当前需要搜索 Dashboard、询问同事、尝试指标名或手写 PromQL。问题并不是不会操作 Grafana，而是用户意图与真实监控资源之间缺少一层可理解的连接。

### 1.2 固定 Dashboard 没有当前需要的视角

> 当已有 Dashboard 没有覆盖当前排查维度时，我希望临时生成和调整图表，在同一处继续追问，而不是打开多个 Dashboard 和 Explore 页面反复切换。

固定 Dashboard 适合稳定监控，但不能预先覆盖所有临时问题。分析需要允许试错、追加视角和修改查询，同时避免把试验图写入共享 Dashboard。

### 1.3 分析结束后，过程和经验容易丢失

> 当一次排查完成后，我希望以后还能恢复当时的问题、查询、图表、调整和结论，并让同事在自己的服务和时间范围上继续分析，而不是只剩一张截图或一段聊天记录。

只保存最终 PromQL 不能说明为什么查询、如何缩小范围、哪些尝试失败，也不能复用完整分析过程。

### 1.4 团队有经验，但缺少合适的使用方式

> 当团队已经形成成熟的指标解释和排查方法时，我希望 Agent 能在合适的问题中自动参考这些经验；对于已经固定、可重复的流程，我希望能够填写参数后执行，而不是每次重新组织 Prompt。

团队经验包含两种不同内容：

- “遇到这类问题应关注什么、如何选择和解释”，属于供 Agent 加载的 Skill；
- “使用哪些参数、按哪些步骤运行”，属于可执行的 Playbook。

### 1.5 告警已经发生，但分析还没有开始

> 当 Grafana 告警触发时，我希望系统能够可信地接收告警，自动执行团队已经发布的只读分析流程，并把关键证据、分析结果和会话链接推送给值班团队，而不是只收到一条没有上下文的告警文本。

现有通知只能说明“发生了什么告警”，值班人员仍需打开 Grafana、寻找指标、执行 SOP 和整理证据。重复告警还可能造成重复劳动。

### 1.6 关键操作发生后无法完整追溯

> 当安全、合规或 SRE Lead 需要调查一次模型、工具、Playbook、分享或审批行为时，我希望知道谁在什么会话中执行了什么、结果如何、谁确认了高风险操作，同时不在日志中暴露密码和 Token。

普通运行日志往往缺少用户、会话和资源关联，也不能完整记录知识检索、Skill 加载、告警触发和审批决定。

### 1.7 共同需求

上述场景的共同需求不是增加一个通用聊天机器人，而是：

> 以用户的观测问题或可信告警为起点，由 Agent 把真实指标、查询、图表、连续分析和团队经验组织成一条透明、可验证、可恢复、可复用且可追溯的分析过程。

## 2. 目标用户

### 2.1 主要用户

| 用户 | 典型任务 | 当前困难 | 期望价值 |
|---|---|---|---|
| SRE / 运维工程师 | 告警排查、巡检、复盘 | 高压环境下仍需找面板、写查询、拼接证据 | 更快得到第一张可信图，并连续缩小问题范围 |
| 后端开发工程师 | 发布验证、接口异常分析、服务健康检查 | 了解业务，但不熟悉复杂 PromQL 和内部指标体系 | 用业务语言开始分析，同时能够检查和修改查询 |
| 平台工程师 | 维护 Grafana、指标规范和团队分析方法 | 反复回答指标在哪里、查询怎么写 | 把成熟查询和分析经验交给 Agent 复用 |

### 2.2 次要用户

- 新加入团队、了解服务但不熟悉监控体系的工程师；
- 具备基本 Grafana 概念、需要查看业务指标的产品或运营人员；
- 需要恢复、查看或复制其他人分析过程的协作成员；
- 负责查看审计日志的合规、安全人员和 SRE Lead；
- 负责 Review shared Skill/Playbook 的 Grafana Folder Admin。

### 2.3 不是首要用户

- 完全不了解服务、指标和时间范围的普通终端用户；
- 需要复杂数据建模和报表制作的数据分析师；
- 需要自动修复、发布编排或事故指挥的运维自动化团队；
- 需要跨企业、多租户商业化管理的平台运营者。

## 3. 现有做法及其不足

### 3.1 固定 Dashboard

适合长期稳定监控和团队共享，但不能覆盖所有临时排查视角。为了临时问题修改共享 Dashboard，容易产生噪音和维护负担。

### 3.2 Grafana Explore 与手写 PromQL

灵活、真实、适合熟练用户，但要求用户先知道指标、标签和查询语言。多个分析视角之间的上下文需要手工维护。

### 3.3 截图、群聊和人工转述

发送迅速，但缺少查询来源、时间范围和上下文，难以更新、回放、验证和复用。

### 3.4 Wiki、Runbook 和 SOP

能够记录经验和责任边界，但通常脱离实时数据。用户仍需自行找到文档、理解步骤并在 Grafana 中重新操作，内容也容易过期。

### 3.5 通用 AI 聊天工具

自然语言交互简单，但缺少当前 Grafana 上下文、真实指标权限和执行证据，容易生成看似合理但无法验证的查询或结论。

### 3.6 Grafana Alert 与普通通知 Webhook

能够及时通知异常，但通常只包含告警文本和标签。值班人员仍需手动打开页面、执行分析步骤和整理证据；重复或伪造请求也需要额外处理。

### 3.7 进程日志和零散审计记录

适合排查单个服务故障，但通常缺少统一事件模型、用户与会话关联、敏感字段脱敏、保留策略和高风险确认记录。

### 3.8 产品机会

Torchbearing 不替代 Grafana、Explore 或团队文档，而是在它们之间补上缺失的一层：

```text
用户提出观测问题
  → Agent 理解问题和当前上下文
  → 找到真实指标
  → 生成并执行透明查询
  → 得到临时图表
  → 继续追问和调整
  → 自动保存分析过程
  → 用户固定重要图表
  → 沉淀和复用团队经验
  → 对可信告警复用已发布的只读流程
  → 用审计日志追溯关键行为
```

## 4. 产品范围与明确不做

本章按能力逐项说明“做什么”和“明确不做什么”，两者共同构成该能力的产品边界。

最终产品包含十项相互配合的功能：

| 编号 | 功能 | 用户获得的能力 |
|---|---|---|
| F1 | 自然语言 Prometheus 指标分析 | 用观测问题开始分析，由 Agent 选择或询问必要上下文并返回真实查询和图表 |
| F2 | 多轮分析与 PromQL 协作编辑 | 围绕已有图表继续追问，并通过自然语言或直接编辑调整查询 |
| F3 | 自动保存与管理分析会话 | 保存、恢复、查找、归档和删除完整分析过程 |
| F4 | 多图工作台与手动保存 | 同屏比较和编辑多张临时图，并由用户明确固定值得继续使用的图表 |
| F5 | 指标与分析知识检索 | 从真实指标信息、成熟查询和受控团队知识中检索与当前问题相关的依据 |
| F6 | Skill 自动加载与管理 | Agent 自动参考团队信息，用户创建和编辑 private Skill，并申请晋升为 shared |
| F7 | Playbook 创建、管理与受控执行 | 用户管理 private Playbook，从界面启动或由 Agent 调用，并申请晋升为 shared |
| F8 | 会话分享与团队经验复用 | 分享带有效期的会话快照、创建副本，并通过 Review 共享经验资产 |
| F9 | 告警触发的自动分析 | 接收可信 Grafana Alert，自动匹配并执行只读 Playbook，再推送带证据的分析结果 |
| F10 | 全链路审计日志 | 记录模型、工具、知识、Skill、Playbook、告警、分享和审批等关键行为 |

### 4.1 F1 自然语言 Prometheus 指标分析

**做**

产品在 Grafana 中提供自然语言驱动的 Prometheus 指标分析功能，包括：

- **自然语言分析入口**：用户可以直接描述想观察的对象、现象、时间范围和比较维度，无须先编写 PromQL；
- **上下文选择与补充**：系统结合用户输入、当前 Grafana 页面和会话历史选择数据源及指标；信息不足或存在明显歧义时，展示候选或向用户询问；
- **主动指定上下文**：用户可以通过 `@datasource`、`@dashboard`、`@service` 和 `@folder` 指定本轮分析需要参考的上下文；
- **PromQL 生成与真实查询**：系统生成可查看的 PromQL，并对真实 Prometheus 数据执行查询；
- **分析结果呈现**：结果同时包含文字说明、PromQL、数据源、时间范围、执行状态和临时图表；
- **流式过程反馈**：分析过程中持续展示文字、工具调用、图表和完成状态，使用户能够看到当前进展；
- **异常与权限反馈**：无数据、查询失败或权限不足时展示真实状态，不使用虚构指标、数据或结论填补结果。

上下文选择遵循以下优先级：

```text
用户显式指定
  → 当前 Grafana 与会话上下文
  → Agent 根据可靠信息选择
  → 存在明显歧义或风险时询问用户
```

**明确不做**

- 只把 Prometheus metrics 作为产品主信号，不把 Loki、Tempo、SQL、Elasticsearch 等作为完整产品能力；
- 不在没有真实查询证据时给出确定性根因，不承诺自动 RCA；
- 不用模型生成的示例数据代替真实查询结果；
- 不因自然语言输入或 `@` 提及扩大用户原有的数据权限；
- 不以语音、截图理解、文件输入等多模态交互代替核心文本分析流程。

### 4.2 F2 多轮分析与 PromQL 协作编辑

**做**

产品提供围绕同一分析过程持续追问和协作修改查询的功能，包括：

- **连续追问**：用户可以围绕已有问题、回答和图表继续提问，无须在每一轮重复服务、数据源和时间范围；
- **指代承接与澄清**：系统能够承接“上一张图”“那个服务”等上下文；存在多个可能对象时，先请用户确认；
- **自然语言调整**：用户可以要求追加图表、修改查询条件、改变分组方式或解释现有结果；
- **PromQL 直接编辑**：用户可以直接查看和修改当前图表使用的 PromQL；
- **修改结果同步**：用户修改后的 PromQL 成为该图表的当前查询，并自动进入后续对话上下文；
- **当前查询透明展示**：每轮分析都展示实际采用的数据源、时间范围和 PromQL，使用户能够检查分析依据。

**明确不做**

- 不把 Agent 对上下文的猜测隐藏起来；
- 不在指代不清时静默修改错误图表；
- 不用 Agent 之前生成的 PromQL 覆盖用户直接修改后的当前查询；
- 不把分析工作台建设成 Grafana Explore 或 Panel Editor 的完整复制品；
- 不建设多人同时编辑同一会话的实时协作能力。

### 4.3 F3 自动保存与管理分析会话

**做**

产品提供自动保存、恢复和管理分析会话的功能，包括：

- **自动保存**：持续保存用户与 Agent 的消息、分析上下文、PromQL 修改、临时图表及执行状态；
- **分析记录留存**：保存可检查的工具使用记录、知识来源、Skill 加载记录以及 Playbook 运行结果；
- **会话恢复**：用户刷新页面或重新进入后，可以恢复此前的分析过程并继续追问；
- **会话查找**：用户可以查看会话列表，并按时间、标题和服务查找历史会话；
- **会话管理**：用户可以重命名、归档、恢复和删除会话；归档会话保持只读，删除会话同时删除其未独立分享的关联内容。

**明确不做**

- 不要求用户记住并执行“保存会话”；
- 不把会话理解为只保存聊天文本，查询、图表和必要执行记录也属于分析过程；
- 不因为自动保存而改变会话的私有性和用户原有权限；
- 不承诺长期保存完整 Prometheus 原始时序数据；
- 不提供跨 Grafana 账号的会话迁移和 PDF 导出。

### 4.4 F4 多图工作台、临时图表与手动保存

**做**

产品提供在一个工作台中查看、调整和保存多张分析图表的功能，包括：

- **临时图表**：分析生成的图表默认作为临时图表进入会话，不自动修改 Grafana Dashboard 或其他共享资产；
- **多图比较**：用户可以在同一工作台中同时查看多张图表；
- **工作台整理**：用户可以拖动排序、调整布局、关闭或删除图表，并以单图全屏方式查看细节；
- **图表修改**：用户可以重新执行图表，通过自然语言调整图表，或直接编辑其 PromQL；
- **手动保存**：用户可以点击“保存”，或者明确要求保存指定图表，将其固定为当前会话中的重要对象，便于后续对比、引用和分享；
- **保存结果反馈**：保存成功后明确显示已保存的目标；“这张图不错”等模糊表达不会触发保存；
- **工作台自动恢复**：图表、布局和保存状态随会话自动记录，刷新或重新进入后可以恢复。

**明确不做**

- 图表保存只表示固定在当前分析会话中，不等于写入 Grafana Dashboard；
- 不根据模糊表达自动保存；
- 不自动固定 Agent 或 Playbook 产生的所有图表；
- 不默认创建、覆盖或删除 Dashboard Panel；
- 不建设 Grafana Scenes 复杂编排、图表模板市场或多人实时协作画布。

### 4.5 F5 指标与分析知识检索

**做**

产品提供面向指标分析的受控知识检索功能，包括：

- **指标信息检索**：查找服务关联的关键指标、指标说明、查询表达式和参考阈值；
- **服务关系检索**：查找团队确认的服务、环境与关键指标之间的关系；
- **成熟查询检索**：查找 Grafana Dashboard 中实际使用的 PromQL，以及团队验证过的查询示例；
- **分析资料检索**：查找有权访问的 Runbook、团队文档和样例问答。
- **来源展示**：关键知识参与查询生成或结果解释时，向用户展示其名称、来源、适用范围或版本；
- **无结果反馈**：找不到可靠知识时明确说明，并通过指标候选或向用户询问继续分析；
- **真实数据校验**：检索结果只作为分析依据，最终观测结果仍以真实 Prometheus 查询为准。

检索采用何种索引、排序或语义匹配方式，由后续设计决定，不作为用户必须理解的产品概念。

**明确不做**

- 不建设任意文档均可导入、编辑、同步和共享的通用企业知识库；
- 不把模型自身记忆或未经验证的文本当作团队事实；
- 不检索或展示用户无权访问的指标信息、Dashboard 内容和团队资料；
- 不用知识检索结果代替真实 Prometheus 查询和执行证据；
- 不要求用户理解或操作 RAG、向量库、Embedding 等实现概念。

### 4.6 F6 Skill 自动加载与管理

**做**

Skill 是供 Agent 参考的分析说明、示例和团队信息。产品提供：

- **自动匹配**：根据当前问题和 Skill 描述，自动选择并加载相关 Skill；
- **对话内指定**：用户可以在自然语言问题中要求加载、优先考虑或排除某个 Skill；
- **使用信息展示**：用户可以查看本轮加载的 Skill 名称、版本和来源；
- **private Skill 创建**：任何已登录用户都可以创建自己的 private Skill；
- **Skill 编辑器**：用户可以查看、编辑、更新和删除自己的 private Skill；
- **从会话生成草稿**：用户可以将会话中的分析经验生成 private Skill 草稿，再继续编辑和确认；
- **共享申请**：用户可以为自己的 private Skill 选择目标 Grafana Folder 并申请成为 shared。

**明确不做**

- 不提供 `run_skill`、Skill dry-run、参数表单、运行状态或独立执行结果；
- 不把 Skill 设计成固定步骤的轻量 Playbook；
- 不通过 Skill 增加 Agent 原本不可用的工具或扩大用户权限；
- 不建设面向外部 AI 客户端的通用 Skill 平台，也不建设 Skill Marketplace、评分和评论体系；
- 不让 Agent 自动发布或共享未经 Review 的 Skill。

### 4.7 F7 Playbook 创建、管理与受控执行

**做**

Playbook 是以 YAML 定义、具有参数、步骤、运行状态和结果的标准流程。产品提供：

- **private Playbook 创建**：任何已登录用户都可以创建自己的 private Playbook；
- **Playbook 编辑器**：用户可以通过 YAML 或表单查看、解释、编辑、更新、删除自己的 Playbook，并识别当前版本；
- **从会话生成草稿**：用户可以将会话中的分析过程生成 private Playbook 草稿，再编辑参数和步骤；
- **界面启动**：用户可以浏览有权访问的 Playbook、填写参数并启动运行；
- **对话内调用**：系统可以根据用户意图调用合适的 Playbook；缺少必要参数时，向用户询问；
- **运行过程展示**：Playbook 的步骤、状态和结果进入当前会话，用户可以查看执行进度；
- **高风险确认**：涉及写操作或高风险动作时，执行前展示目标、参数和影响，并获得用户确认；
- **图表结果处理**：Playbook 产生的图表默认为临时图表，只有用户明确保存后才固定到会话工作台；
- **共享申请**：用户可以为自己的 private Playbook 选择目标 Grafana Folder 并申请成为 shared。

**明确不做**

- 不运行任意脚本，不动态调用未声明工具，不调用另一个 Playbook；
- 不在参数不足时使用高风险猜测补全；
- 不自动执行未经确认的写操作或高风险动作；
- 不把 Playbook 生成的所有图表自动保存为长期对象；
- 不自动发布、扩缩容、重启服务、修改告警规则或变更生产配置；
- 不让 Agent 自动发布或共享未经 Review 的 Playbook。

### 4.8 F8 会话分享与团队经验复用

**做**

产品提供会话分享、独立复用和经验资产共享功能，包括：

- **会话快照分享**：分享会话时创建稳定快照，源会话后续修改不改变已经分享的内容；
- **有效期管理**：分享默认使用系统设置的 TTL，分享者也可以选择永不过期，或者随时撤销并删除快照；
- **团队内访问**：同一 Grafana 团队内的已登录成员可以访问有效快照；访问不会扩大其原有数据和资产权限；
- **创建独立副本**：接收者可以从快照创建自己的会话副本并继续分析，不修改源会话；快照过期或撤销不影响已经创建的副本；
- **个人与团队资产区分**：private Skill/Playbook 与团队 shared 资产具有明确标识和不同权限；
- **共享申请**：创建者选择目标 Grafana Folder，为 private Skill 或 Playbook 提交共享申请；
- **Folder Review**：目标 Folder Admin 可以查看申请内容并通过或拒绝；
- **共享权限复用**：通过后资产成为 shared，其查看、编辑和使用权限遵循 Grafana Folder Permission；
- **过程留痕**：资产创建、共享申请和 Review 结果均被记录。

**明确不做**

- 不让接收者直接修改分享者的源会话；
- 不因分享、复制、Fork 或共享晋升绕过数据权限；
- 不由 AI 自动审批 shared 资产；
- 不提供 private / shared / global 三层可见性，跨范围共享使用约定的 Shared Folder；
- 不建设评分、投票、Marketplace、多租户商业化、计费或 License 平台；
- 不把内部 Agent、Skill、Playbook 或 MCP Server 建设成面向外部客户端的通用公共平台。

### 4.9 F9 告警触发的自动分析

**做**

产品提供由 Grafana 告警自动启动标准分析流程的功能，包括：

- **可信告警接入**：接收 Grafana Alert，并识别来源无效、已经过期或重复到达的告警；
- **分析流程配置**：由团队将告警名称和标签明确关联到已发布的只读 Playbook；
- **告警参数带入**：将告警标签带入 Playbook 参数；缺少必要配置时明确显示失败原因，不猜测执行；
- **自动分析**：有效告警按照既定配置启动分析，无须值班人员先手动发起；
- **运行状态跟踪**：展示等待、分析中、成功、失败、重试、超时和取消等状态；
- **分析结果通知**：向配置的团队通知目标发送告警摘要、分析步骤、真实查询证据、分析结论和会话链接；
- **过程追溯**：保留告警接收、重复判断、Playbook 运行和结果通知记录。

**明确不做**

- 不对没有明确映射的告警猜测并执行 Playbook；
- 不在无人确认的告警链路中执行写操作或高风险步骤；
- 不替代 Grafana Alert 的静默、抑制和告警规则管理；
- 不把分析建议表述为确定性根因；
- 不建设复杂的多通知通道路由和模板平台。

### 4.10 F10 全链路审计日志

**做**

产品提供以日志形式记录和查询关键行为的审计功能，包括：

- **分析过程审计**：记录用户、会话、请求以及模型调用的时间、状态、耗时和必要元数据；
- **工具与知识使用审计**：记录系统工具调用、知识来源、Skill 加载和 Playbook 运行的状态与结果摘要；
- **告警分析审计**：记录告警接收、重复判断、自动分析和结果通知；
- **用户操作审计**：记录图表保存、会话分享、撤销和删除；
- **经验资产审计**：记录 Skill/Playbook 的创建、更新、删除、共享申请和 Review；
- **高风险确认审计**：记录操作目标、确认人、确认结果和必要的变更差异；
- **敏感信息保护**：记录前对密码、Token、Cookie、Authorization 和自定义敏感字段进行脱敏；
- **保留与授权访问**：支持配置日志保留时间，只允许授权的合规、安全和运维人员查询。

**明确不做**

- 不记录或展示模型的隐藏思维过程；
- 不以明文记录密码、Token、Cookie、Authorization 等敏感字段；
- 不允许普通用户修改或删除审计日志；
- 不建设审计日志专用的实时告警、商业化合规平台或复杂查询产品；
- 审计写入失败时不得伪装成成功，必须产生可观测的降级状态。

## 5. 关键决策与依据

### 5.1 嵌入 Grafana，而不是独立建设分析门户

| 方案 | 判断 |
|---|---|
| Grafana 内的分析工作台 | 选择。用户已经在 Grafana 中查看数据，可以沿用熟悉的入口、上下文和权限心智。 |
| 独立 Web 产品 | 暂不选择。用户需要在两个系统之间切换，产品还需要重新建立监控资源和权限语义。 |
| 纯聊天机器人 | 不选择。分析需要图表、查询、状态和多视角工作空间，不能只有消息列表。 |

### 5.2 由 Agent 组织分析，而不是要求用户先填全参数

| 方案 | 判断 |
|---|---|
| Agent 使用用户输入和当前上下文完成选择，必要时询问 | 选择。符合自然语言分析的核心价值，同时保留用户纠正空间。 |
| 所有数据源、指标和时间范围都要求用户先选择 | 不选择。仍然要求用户先理解监控资源，削弱自然语言入口价值。 |
| Agent 始终自行决定，不向用户澄清 | 不选择。歧义会产生错误查询，也不利于用户信任。 |

### 5.3 Prometheus-first，而不是同时铺开所有信号

| 方案 | 判断 |
|---|---|
| 以 Prometheus metrics 作为产品主信号 | 选择。能够用真实数据完成核心分析，产品边界清楚。 |
| Metrics、Logs、Traces 同时支持 | 不选择。不同信号的语义、查询和展示差异较大，会稀释首个闭环。 |

### 5.4 临时图优先，保存与 Dashboard 写入分离

| 方案 | 判断 |
|---|---|
| 临时图自动进入会话历史，用户明确固定重要图表 | 选择。既能恢复分析过程，又保留用户对重要资产的控制。 |
| 所有图表自动固定 | 不选择。一次分析可能产生大量试验结果，容易使工作台失去重点。 |
| 自动创建或更新 Dashboard | 不选择。错误查询和试验图容易污染正式监控资产。 |

### 5.5 会话自动保存，而不是依赖用户记得保存

| 方案 | 判断 |
|---|---|
| 自动保存会话 | 选择。连续分析不应因为刷新、离开页面或忘记保存而丢失。 |
| 用户手动保存会话 | 不选择。增加额外负担，也容易造成分析过程丢失。 |

### 5.6 查询透明，而不是只给黑盒答案

| 方案 | 判断 |
|---|---|
| 展示 PromQL、数据源、时间范围和状态 | 选择。用户可以检查、修改、复制和复现结果。 |
| 只给 AI 摘要或结论 | 不选择。用户无法判断结论是否来自真实数据，也难以及时发现错误。 |

### 5.7 检索受控知识，而不是依赖模型记忆

| 方案 | 判断 |
|---|---|
| 检索真实指标信息、成熟查询和受控团队知识，并保留来源 | 选择。能够提高指标选择和 PromQL 质量，也便于用户检查依据。 |
| 主要依赖模型自身记忆生成指标和解释 | 不选择。组织内部指标和查询难以从模型记忆获得，结果也无法追溯。 |
| 建设能够管理任意企业文档的通用知识平台 | 不选择。范围过大，且偏离指标分析主线。 |

### 5.8 Skill 与 Playbook 分别承担信息和执行

| 方案 | 判断 |
|---|---|
| Skill 是 Agent 自动加载的信息，Playbook 是可执行流程 | 选择。信息加载和流程执行具有不同的用户心智与安全边界。 |
| Skill 和 Playbook 都可运行 | 不选择。概念重叠，也会使权限、状态和结果归属不清。 |
| Template、Runbook、Skill、Workflow 并列 | 不选择。顶层概念过多，用户难以判断应使用哪一种资产。 |

### 5.9 用户和 Agent 均可启动 Playbook

| 方案 | 判断 |
|---|---|
| 用户从界面启动，Agent 也可按意图作为工具调用 | 选择。兼顾明确入口和自然语言分析体验。 |
| 只能由用户从列表启动 | 不选择。Agent 无法复用已验证流程完成用户请求。 |
| Agent 可以无条件执行所有 Playbook | 不选择。写操作和高风险动作必须由用户确认。 |

### 5.10 每个用户先创建 private 资产，再申请共享

| 方案 | 判断 |
|---|---|
| 所有人可创建自己的 private Skill/Playbook，申请后由 Folder Admin Review | 选择。允许个人试用和修改，同时保证 shared 资产具有明确责任人。 |
| AI 从会话提取后立即发布 | 不选择。错误经验会被放大并重复使用。 |

### 5.11 会话分享采用同团队快照和可配置有效期

| 方案 | 判断 |
|---|---|
| 同一 Grafana 团队访问冻结快照，默认 TTL、可设永不过期、可提前撤销 | 选择。分享边界清楚，也不让源会话后续修改影响接收者。 |
| 指向持续变化的源会话 | 不选择。分享后新增内容可能被意外暴露，接收者也无法得到稳定依据。 |
| 完全公开的匿名链接 | 不选择。无法复用 Grafana 登录态和团队权限。 |

### 5.12 告警只触发明确映射的只读 Playbook

| 方案 | 判断 |
|---|---|
| 告警映射到已发布的只读 Playbook，再异步执行和推送结果 | 选择。流程可预测、可审计，且无人值守时不会触发副作用。 |
| Agent 根据告警自由规划和执行 | 不选择。无人确认时无法安全处理歧义和高风险操作。 |
| 自动执行写操作 Playbook | 不选择。告警链路中没有可靠的即时确认主体。 |

### 5.13 审计采用不可由普通用户修改的脱敏日志

| 方案 | 判断 |
|---|---|
| 全链路事件写入脱敏审计日志，并按授权访问 | 选择。能够追溯模型、工具、资产、告警和审批行为。 |
| 只依赖进程标准输出 | 不选择。无法保证保留、关联和合规查询。 |
| 记录完整 Prompt、密钥和模型隐藏思维过程 | 不选择。会增加敏感信息泄露风险，也不属于必要审计证据。 |

## 6. 基本概念与信息结构

本节只定义用户能够理解或感受到的产品概念，不规定数据库表、接口字段或具体框架。

### 6.1 产品运行形态

产品由三个职责清楚的单元共同完成用户体验：

```text
Grafana Plugin 前端
  → Server 后端（包含 Agent Core）
  → 普通 MCP Server（向 Agent 提供工具）
  → Prometheus / Grafana 等真实数据源
```

- Plugin 是用户界面，负责输入、状态展示和图表交互；
- Server 是产品后端，Agent Core 在其中理解问题、维护上下文、选择能力并组织结果；
- MCP Server 是普通 MCP 工具服务器，为 Agent 提供查询等能力，不承担产品界面和会话主体；
- 用户只通过插件使用产品，不直接操作 MCP Server。

### 6.2 分析问题

用户想从监控数据中回答的问题，通常包含对象、现象、时间范围和可选比较维度，但不要求用户每次填写完整。

### 6.3 分析上下文

Agent 理解当前问题所需的信息，包括：

- 用户显式输入；
- 用户通过 `@datasource`、`@dashboard`、`@service` 或 `@folder` 指定的信息；
- 当前 Grafana 数据源、Dashboard、Folder 和时间范围；
- 当前会话中的服务、图表和查询；
- 用户直接修改后的 PromQL；
- 与当前问题相关的指标和分析知识；
- 本轮加载的 Skill；
- 已完成的 Playbook 结果。

上下文只帮助 Agent 理解问题，不会扩大用户权限。

### 6.4 分析回复

Agent 对一次问题的反馈，可以包含：

- 对问题和上下文的理解；
- 澄清问题或候选；
- 查询进度和工具事件；
- 采用的指标或分析知识来源；
- PromQL、数据源和时间范围；
- 临时图表；
- 基于真实结果的解释；
- 错误状态和恢复建议。

分析回复以流式事件逐步到达，包括文字增量、工具调用、工具结果、图表、等待确认、错误和结束状态。

### 6.5 分析会话

用户围绕一个问题持续进行的分析过程，是消息、上下文、查询、图表、知识检索、Skill 加载和 Playbook 运行的共同载体。

会话自动保存，用户刷新页面或重新进入后可以恢复分析过程。会话可以被查找、重命名、归档、恢复和删除。

### 6.6 图表

图表是会话中的独立分析结果，不只是聊天文本附件。

图表同时具有两类用户可感知状态：

- 生命周期：临时、已保存、已关闭；
- 执行状态：加载中、成功、无数据、失败、已过期。

一张已保存图表在 PromQL 被修改后，可以同时处于“已保存”和“已过期”状态，重新执行后更新结果。

### 6.7 查询修订

同一图表的 PromQL 可以由 Agent 生成、由用户直接修改、由用户通过自然语言调整，或由 Agent 根据错误修正。当前最终 PromQL 是后续查询和 Agent 上下文的事实来源。

### 6.8 指标与分析知识

Agent 为完成指标选择、PromQL 生成和结果解释而检索的受控信息，包括指标元数据、服务与指标关系、成熟查询和团队维护的分析资料。知识应保留来源和适用范围，并受用户原有权限约束。

知识检索是通用的信息查找能力；Skill 是具有明确名称、描述和版本，由 Agent 按场景加载的一组结构化分析指导。二者可以关联，但不是同一个产品对象。

### 6.9 Skill

团队发布给 Agent 的分析信息。Agent 根据 Skill 描述和当前问题自动加载；用户可以通过自然语言要求加载或排除，但不存在 Skill 运行。

Skill 具有 private 和 shared 两种可见性。任何用户都可以创建和编辑自己的 private Skill；shared Skill 绑定 Grafana Folder，并经过 Folder Admin Review 后供有权限的成员使用。

### 6.10 Playbook 与 Playbook Run

- Playbook：具有参数和步骤的 YAML 流程定义；
- Playbook Run：某次真实执行，包含发起来源、参数、步骤状态、结果和必要的确认记录。

Playbook Run 属于当前会话，发起来源可以是用户界面或 Agent。

Playbook 同样具有 private 和 shared 两种可见性。任何用户都可以创建和编辑自己的 private Playbook；shared Playbook 绑定 Grafana Folder，并经过 Folder Admin Review 后供有权限的成员使用。

### 6.11 会话快照与副本

- 快照：某个时刻冻结、可分享且不随源会话继续变化的分析内容；默认有 TTL，也可以设置为永不过期；
- 撤销：使分享快照立即过期并按删除处理，之后无法继续访问或创建副本；
- 副本：接收者基于快照创建的新会话，后续修改不影响原内容。

有效快照只允许分享者所在 Grafana 团队的已登录成员访问。撤销或过期不删除此前已经创建的独立副本。

### 6.12 告警分析

- 告警事件：来自 Grafana Alert、经过可信校验和去重的触发信息；
- 告警映射：告警名称、标签与已发布只读 Playbook 之间的明确关系；
- 告警分析运行：由告警自动触发的 Playbook Run，具有等待、运行、成功、失败、超时和取消状态；
- 告警分析结果：包含告警摘要、查询证据、分析说明、Playbook 结果和会话链接，可推送到团队通知目标。

### 6.13 审计日志

对模型、工具、知识、Skill、Playbook、告警、图表、分享和审批等关键行为的不可变事件记录。审计日志关联用户、会话、请求、资源、状态和时间，并对敏感字段进行脱敏。

### 6.14 核心关系

```text
Session（自动保存）
├─ Message / 本轮上下文
├─ Chart
│  ├─ 当前 PromQL
│  ├─ 查询修订历史
│  └─ 执行状态
├─ 知识检索记录与来源
├─ Skill 加载记录
├─ Playbook Run
└─ Audit Event

Session
  ├─ 分享为快照并创建副本
  └─ 整理形成 Skill 或 Playbook 草稿

private Skill / Playbook
  → 申请共享到 Grafana Folder
  → Folder Admin Review
  → shared Skill / Playbook

Grafana Alert
  → 告警映射
  → 只读 Playbook Run
  → 分析结果与会话链接
  → 团队通知目标
```

## 7. 原型 / Demo

### 7.1 工作台信息区域

原型应表现一个完整的 Grafana 内分析工作台，至少包含：

- **会话区域**：创建、搜索、重命名、归档、恢复、删除和分享自动保存的会话；
- **对话与输入区域**：输入自然语言问题或 `@` 上下文，查看流式文字、澄清问题、工具事件、图表事件和结束状态；
- **当前上下文区域**：显示当前数据源、时间范围、服务、Dashboard、当前图表和当前 PromQL；
- **图表工作台**：并列展示临时图表和已保存图表，支持拖动排序、调整布局、全屏、直接编辑 PromQL、重新执行、保存和关闭；
- **知识来源信息**：显示 Agent 采用的指标元数据、成熟查询或团队资料的名称、来源和适用范围；
- **Skill 使用信息**：显示 Agent 本轮自动加载的 Skill 名称、版本和来源，不出现 Skill 运行按钮；
- **Skill/Playbook 管理区域**：查看和编辑自己的 private 资产，创建、更新、删除、申请共享，并查看 Review 状态；
- **Playbook 入口**：浏览和选择有权访问的 Playbook、填写必要参数、查看运行步骤和结果；
- **确认区域**：Playbook 涉及写操作或高风险动作时，展示目标、参数、影响和确认操作。
- **告警分析区域**：查看告警、匹配的 Playbook、运行状态、关键证据、推送状态和关联会话。

### 7.2 关键交互

原型应能够演示以下连续行为：

1. 用户输入一个观测现象并通过 `@service` 或 `@datasource` 补充上下文，Agent 使用这些信息选择真实指标并生成 PromQL；
2. 信息不足时，Agent 在执行查询前提出澄清问题或展示候选；
3. 查询过程中用户持续看到流式文字、工具事件和图表事件；查询成功后看到 PromQL、数据源、时间范围、状态和临时图表；
4. 用户围绕已有图表继续追问，或直接修改 PromQL 后继续与 Agent 对话；
5. 用户点击“保存图表”或明确要求 Agent 保存，将目标图表固定到当前会话；
6. 页面刷新或重新进入后，会话、上下文和图表恢复；用户可以搜索、归档、恢复或删除会话；
7. Agent 检索与当前问题相关的指标和分析知识，并展示采用的关键来源；
8. Agent 自动加载匹配的 Skill，并在分析详情中展示加载记录；
9. 用户从界面启动 Playbook，或者 Agent 根据问题调用 Playbook；
10. 高风险 Playbook 等待用户确认后才继续执行；
11. 用户创建并编辑 private Skill 或 Playbook，选择目标 Folder 申请共享，Folder Admin 通过或拒绝；
12. 用户将会话分享为稳定快照，选择默认 TTL、永不过期或提前撤销，同团队成员从有效快照创建自己的副本；
13. Grafana Alert 触发已映射的只读 Playbook，完成分析并向团队通知目标推送结果和会话链接。

### 7.3 必须覆盖的状态

- 空会话；
- Agent 正在理解或等待用户澄清；
- 正在查询；
- 查询成功；
- 查询无数据；
- 查询失败或超时；
- 权限不足；
- 流式连接中断和恢复；
- 临时图表、已保存图表和已关闭图表；
- PromQL 已修改但尚未重新执行；
- 找到可信知识来源、未找到相关知识和知识无权访问；
- Playbook 等待参数、运行中、等待确认、成功、失败和已中止；
- Skill 已自动加载、用户指定加载和用户要求排除；
- private 资产草稿、申请共享、Review 通过和 Review 拒绝；
- 分享快照有效、永不过期、已过期和已撤销；
- 告警未匹配、已去重、等待运行、分析中、推送成功、推送失败和超时。

## 8. 验收标准

### 8.1 代表性主流程

- [ ] 已登录用户可以在 Grafana Plugin 中输入自然语言问题，问题被交给 Server 中的 Agent；
- [ ] 用户只说“查看 checkout 服务最近的请求速率”时，Agent 能使用当前上下文选择数据源和时间范围，或者在依据不足时向用户询问；
- [ ] 用户可以通过 `@datasource`、`@dashboard`、`@service` 和 `@folder` 带入上下文，且每项上下文均经过权限校验；
- [ ] Agent 通过 MCP Server 提供的工具执行真实 Prometheus 查询，而不是仅生成示例结果；
- [ ] Agent 以流式文字、工具调用、工具结果、图表、错误和结束事件反馈处理过程，连接中断时具有明确状态；
- [ ] 成功结果同时展示 PromQL、实际数据源、实际时间范围、执行状态和一张临时图表；
- [ ] 用户可以围绕已有图表继续追问，指代不清时 Agent 会澄清；
- [ ] 用户直接修改 PromQL 后，下一轮 Agent 获得修改后的 PromQL，并以其为当前查询事实来源；
- [ ] 会话自动保存，刷新或重新进入后可以继续分析；
- [ ] 用户可以按时间、标题或服务查找会话，并完成重命名、归档、恢复和删除；
- [ ] 用户可以同时查看多张图表，并完成拖动排序、调整布局、关闭、全屏、重新执行和直接编辑 PromQL；
- [ ] 用户点击“保存图表”或明确要求 Agent 保存后，目标图表被固定到当前会话，并得到明确反馈；
- [ ] 保存图表不会创建或修改 Grafana Dashboard Panel。

### 8.2 指标与分析知识检索行为

- [ ] Agent 能检索与当前问题相关的指标元数据、服务与指标关系、成熟 PromQL 或受控团队资料；
- [ ] Agent 使用关键知识生成查询或解释结果时，用户可以查看其名称、来源或适用范围；
- [ ] 检索不到可靠知识时，Agent 明确说明，并通过真实指标候选或向用户澄清继续分析；
- [ ] 检索结果不会替代真实 Prometheus 查询，不会被描述成已经发生的观测事实；
- [ ] 用户无权访问的 Dashboard、指标说明或团队资料不会被检索结果泄露；
- [ ] 产品界面不要求用户理解或配置 RAG、向量库、Embedding 等实现概念。

### 8.3 Skill 行为

- [ ] Agent 能根据用户问题与 Skill 描述自动加载匹配的 Skill；
- [ ] 用户可以在自然语言问题中要求加载、优先考虑或排除指定 Skill；
- [ ] 用户可以查看本轮加载的 Skill 名称、版本和来源；
- [ ] 任意已登录用户可以创建 private Skill，并在编辑器中查看、更新和删除自己的 Skill；
- [ ] 用户可以从会话生成 private Skill 草稿，并在保存前编辑内容；
- [ ] Skill 不出现运行按钮、参数表单、运行状态、dry-run 或独立执行结果；
- [ ] 加载 Skill 不会扩大用户权限或为 Agent 增加原本不可用的工具。

### 8.4 Playbook 行为

- [ ] 任意已登录用户可以创建 private Playbook，并在 YAML 或表单编辑器中查看、解释、更新和删除；
- [ ] 用户可以从会话生成 private Playbook 草稿，并在保存前编辑参数和步骤；
- [ ] 用户可以从界面选择、填写参数并启动 Playbook；
- [ ] Agent 可以根据用户意图将 Playbook 作为工具调用；
- [ ] 参数不足时 Agent 会询问用户，不会使用高风险猜测补全；
- [ ] 只读 Playbook 的步骤状态和结果进入当前会话；
- [ ] 写操作或高风险 Playbook 在执行前展示目标、参数和影响，未经确认不执行；
- [ ] Playbook 生成的图表默认是临时图表，不会自动固定或写入 Dashboard。

### 8.5 分享与晋升行为

- [ ] 会话分享创建冻结快照，源会话后续修改不会改变已分享内容；
- [ ] 分享默认使用系统 TTL，分享者也可以选择永不过期；
- [ ] 分享者撤销分享后，快照立即失效并按删除处理，不能继续访问或创建副本；
- [ ] 同一 Grafana 团队内已登录成员可以访问有效快照，团队外用户被拒绝；
- [ ] 从快照创建的副本与源会话独立，快照过期或撤销不会删除已经创建的副本；
- [ ] private Skill/Playbook 可以选择目标 Grafana Folder 申请共享；
- [ ] Folder Admin 可以查看内容并通过或拒绝，未经 Review 不会成为 shared；
- [ ] shared 资产的查看、编辑和使用权限符合 Grafana Folder Permission。

### 8.6 告警触发分析行为

- [ ] 可信 Grafana Alert 能触发一次可追踪的告警分析，重复或过期事件不会重复运行；
- [ ] 只有存在明确映射时才启动已发布的只读 Playbook；
- [ ] 告警标签能够映射为 Playbook 参数，缺失必要参数时记录失败而不是猜测执行；
- [ ] 告警分析具有等待、运行、成功、失败、超时和取消状态；
- [ ] 成功结果包含真实查询证据、分析说明和关联会话，并推送到配置的团队通知目标；
- [ ] 无人值守的告警链路不会执行写操作或高风险步骤。

### 8.7 审计日志行为

- [ ] 模型、MCP 工具、知识检索、Skill、Playbook、告警、分享、资产变更和审批均产生关联用户、会话或资源的审计事件；
- [ ] 高风险确认记录确认人、目标、决定和必要参数差异；
- [ ] 密码、Token、Cookie、Authorization 和自定义敏感字段在日志中被脱敏；
- [ ] 审计日志具有可配置保留时间，只有授权的合规、安全和运维人员可以访问；
- [ ] 普通用户不能修改或删除审计日志；
- [ ] 审计日志不包含模型隐藏思维过程，写入失败产生明确降级状态。

### 8.8 边界与错误

- [ ] 找不到可信指标时，Agent 展示候选或要求澄清，不虚构指标；
- [ ] 查询无数据时保留 PromQL 和时间范围，并明确显示无数据；
- [ ] 查询语法错误、超时或工具失败时展示错误状态，并允许 Agent 修正或用户修改；
- [ ] 用户无权访问数据源或资源时拒绝请求，不返回越权数据；
- [ ] 没有真实查询证据时，Agent 不给出确定性根因结论。

## 附录 A：产品原则与成功信号

### 产品原则

- 先给真实查询证据，再给解释；
- Agent 可以自主选择，但明显歧义和高风险操作必须询问用户；
- 检索知识保留来源，且不能代替真实查询证据；
- 临时分析、保存图表和正式 Dashboard 资产保持区分；
- 用户直接编辑后的 PromQL 优先于 Agent 之前的理解；
- 权限不因自然语言、Skill 或 Playbook 而扩大；
- Skill 只提供信息，Playbook 才负责结构化执行；
- 个人经验先保持 private，经 Folder Admin Review 后才能 shared；
- 告警只运行明确映射的只读 Playbook，不在无人确认时执行副作用；
- 关键行为必须形成脱敏、不可由普通用户修改的审计日志；
- 失败后保留已有上下文，并告诉用户如何继续。

### 核心成功信号

- 用户从提交问题到获得第一张可用图表的时间；
- 流式回复首次产生可见文字或状态的时间；
- 首次 PromQL 是否可执行、是否符合用户意图；
- 用户是否检查、修改或继续使用生成的查询；
- 会话恢复后是否能够继续分析；
- 用户是否主动保存图表，以及保存后是否继续引用；
- 检索到的指标和分析知识是否相关、可追溯并被用户采纳或纠正；
- Skill 是否被正确加载并可追溯，而不是是否“运行成功”；
- Playbook 是否成功完成步骤并产生可检查结果；
- private Skill/Playbook 是否经过有效试用和 Review 后成为 shared；
- 告警触发分析的去重率、成功率、超时率和结果推送成功率；
- 关键行为的审计日志是否完整关联用户、会话、资源和审批结果；
- 是否发生越权查询、未确认高风险操作或未经确认的 Dashboard 写入。
